# JSON取扱いのセキュリティ評価

対象は静的アプリのJSONバックアップ復元、起動時のブラウザ保存読込、別タブのstorage通知です。読み込むファイルと同一オリジンの保存値を信頼境界の外として扱います。ファイルを選択した利用者、または同一オリジンでコードを実行できる者が不正データを供給することが攻撃の前提です。これはサーバーAPIへの遠隔攻撃を意味しません。

| 脅威 | 対策前の評価 | 現在の対策と限界 |
| --- | --- | --- |
| JSONインジェクション・構文の曖昧さ | `JSON.parse`で文法を検査し、既知の装備に再構成。具体的な注入経路は未確認 | パース前にエスケープを解釈した重複キーを拒否し、最終的な文法は`JSON.parse`で検査。スキーマの必須・許可キー、型、値、装備の一意性を検証 |
| プロトタイプ汚染 | `JSON.parse`の`__proto__`はそれだけではプロトタイプを書き換えない。危険なマージ処理も未確認 | 未知キーを拒否し新しい固定形のオブジェクトを構築。将来の変更にも注意が必要（[MDN](https://developer.mozilla.org/en-US/docs/Web/Security/Attacks/Prototype_pollution)） |
| XSS | 装備名は固定リストに限定し、表示箇所は固定文言・エスケープまたは`textContent`を使用。具体的な経路は未確認 | 同じ制限を維持。アプリ全体や将来の変更の安全性を保証するものではない |
| DoS・資源枯渇 | 復元ファイルは2,000,000バイト上限があったが、保存値には上限がなく、検証前に深いコピーも行っていた | 3経路でUTF-8 2,000,000バイト、深さ4、構造トークン4,096、各生文字列1,024 UTF-16コード単位を制限。先に文字数を検査し巨大なエンコード割当を避ける。配列は最大71件。ファイルの読み取りやブラウザ自体の負荷を完全には防げない（[OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Denial_of_Service_Cheat_Sheet.html)、[RFC 8259](https://www.rfc-editor.org/rfc/rfc8259.html)） |
| JSONハイジャック・CSRF | JSONP、非公開JSON API、認証Cookieを使用しないため、これらを標的とする経路は現状ない | 認証やAPIを新たに導入する場合は再評価する |
| JWT | JWTを使用しないため、署名やアルゴリズム検証を標的とする経路は現状ない | JWTを導入する場合は改めて検証する（[RFC 8725](https://www.rfc-editor.org/rfc/rfc8725.html)） |
| 保存データの改ざん | 同一オリジンのスクリプトは保存値を操作できる | 不正な保存値は読み込みを拒否し、起動時は元データの上書きを停止。スキーマに合う改ざんの真正性は判別できない（[MDN 同一オリジン](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy)） |

復元は検証後も明示的な確認まで保存しません。無効な入力は既存記録を変更せず、古い非同期読込や確認ボタンを無効にします。旧版の範囲未満の補正値の移行は起動時のブラウザ保存読込に限ります。

対策前のChromeでの再現確認では、余分な配列を深さ12,000で含む24,100バイトのJSONは`validateBackup`を通過した一方、起動時の`structuredClone`は`RangeError: Maximum call stack size exceeded`になりました。また余分な配列要素100,000個を含む200,100バイトのJSONも`validateBackup`を通過しました。いずれも不正なローカル入力に対する資源処理の問題を示すもので、遠隔から実行できる攻撃を示すものではありません。

JSONの処理にアーカイブ展開やエンティティ展開はなく、参照の展開による指数的な増幅は発生しません。大量の入力や深い入れ子の資源負荷は上記の制限で扱います。
